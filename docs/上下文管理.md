# 上下文管理

> 本文描述 **pamimi-tako-bot-demo 项目内**的上下文管理实现：配置字段、代码接线与数据流向，均以 `core/`、`middleware/`、`configs/` 的现行代码为准。
> 底层机制（注入 / 压缩 / 卸载）由 AgentScope 2.0.7 提供，框架级概念可参考[官方文档](https://docs.agentscope.io)；本文只写本项目「怎么配、怎么接、落在哪」。

## 总览

上下文是智能体的工作记忆：大模型每一步推理看到的全部消息（用户输入、智能体回复、工具调用、工具结果）。本项目围绕它有三种机制，外加会话恢复时的回填与 fork 窗口：

| 机制 | 作用 | 本项目实现 |
| ---- | ---- | ---- |
| **上下文注入** | 把随对话变化的运行时状态（时间、上下文用量、自定义字段）以提示形式注入上下文 | `InjectionConfig` 接线（[core/agent/factory.py](../core/agent/factory.py)），配置在 `agent.injection` |
| **上下文压缩** | 把较早消息汇总成结构化摘要、截断过大的工具结果，长对话不撑爆窗口 | `ContextConfig` 接线，配置在 `agent.context_*` / `agent.tool_result_limit` |
| **上下文卸载** | 被压缩 / 截断的内容持久化到工作区文件，智能体可用 Read/Grep 回查 | `LocalWorkspaceManager` 作为 `offloader` 挂载，落在用户私有域 |
| **回填 / fork 窗口** | 会话从持久化恢复、或 fork 分支时，控制携带多少历史 | `context.backfill_*` / `context.fork_window_turns`（[core/session.py](../core/session.py)） |

配套还有两道防线：**压缩守卫**（`ContextGuardMiddleware`，无卸载器拒绝压缩）与**回复预算**（`ReplyBudgetControlMiddleware`，消耗接近预算时注入收尾提示，见 [budget-control.md](budget-control.md)）。

## 上下文是怎么拼起来的

每次模型调用前，Agent 将三层内容拼成单次 API 输入：

```
模型 API 输入
├── 系统提示        ← configs/prompt.py 的 SYSTEM_PROMPT（agent.system_prompt 配置）
│                     + 技能指令（Toolkit）+ on_system_prompt 中间件转换
├── 摘要            ← 仅压缩发生后存在（name == "summary" 的消息）
└── 上下文          ← 最近未压缩消息 + 注入的运行时状态提示（HintBlock）
```

固定信息（身份、长期指令）写系统提示；会话中**会变化**的信息走运行时注入——注入以 `HintBlock` 追加进上下文而非改系统提示，提示词缓存依然有效。

## 运行时注入

由 `InjectionConfig` 控制，本项目实际取值（`configs/dev.yaml` → `agent.injection`，接线见 factory.py）：

| 字段 | 本项目取值 | 说明 |
| ---- | ---- | ---- |
| `timezone` | `"Asia/Shanghai"` | 注入时间的时区 |
| `time_interval` | `0.5` | 距上次时间记录超过 0.5 小时才刷新时间 |
| `context_buffer_ratio` | `0.15` | 进入压缩阈值前 15% 缓冲区时，注入上下文用量预警 |
| `emit_hint_event` | `true` | 注入时产出 `HintBlockEvent`，前端可渲染注入内容 |
| `extra_fields` | `{"platform": "Pamimi Tako Bot Demo"}` | 每次注入附带的自定义字段 |

注入的三个维度（框架内置）：

- **时间**：上下文无时间记录，或距上次记录超过 `time_interval`；
- **计划任务**：存在未完成任务且上下文无任务相关工具调用时，提醒调用 `TaskList`（需启用任务工具）；
- **上下文用量**：回复第一轮迭代中，输入 token 进入 `context_buffer_ratio` 缓冲区时，预告压缩即将发生。

典型注入形态：

```text
<system-reminder>…<current-time>2026-10-13T10:30:00</current-time>
<timezone>Asia/Shanghai</timezone>
<platform>Pamimi Tako Bot Demo</platform>
</system-reminder>
```

注入**不是临时的**——它追加到持久化上下文中，让智能体感知时间流逝；后来的提醒覆盖先前的。

## 自动压缩

压缩在每次推理步骤前由框架自动执行。`ContextConfig` 本项目实际取值（factory.py 从 `agent.*` 配置注入）：

| 参数 | 本项目取值 | 配置字段 | 说明 |
| ---- | ---- | ---- | ---- |
| `trigger_ratio` | `0.6` | `agent.context_trigger_ratio` | token 用量超过 60%×`llm.context_size`（128K）即触发压缩 |
| `reserve_ratio` | `0.15` | `agent.context_reserve_ratio` | 压缩后保留最近约 15% 窗口的消息 |
| `tool_result_limit` | `15000` | `agent.tool_result_limit` | 单条工具结果 token 上限，超出截断并卸载 |
| `compression_prompt` | 自定义中文提示词 | 代码内置 | 见下 |
| `summary_schema` | 六字段结构化摘要 | 代码内置 | 见下 |

**压缩提示词**要求摘要：保留文件路径 / API 端点 / 错误信息完整原文；保留用户偏好与约束；保留未完成任务与计划；用绝对时间不用相对时间；用完整路径不用相对引用。

**摘要 schema**（六个必填字段，较框架默认多一个 `tool_outputs_summary`）：

| 字段 | 内容 |
| ---- | ---- |
| `task_overview` | 用户核心需求与成功标准 |
| `current_state` | 已完成的工作、修改的文件、关键输出 |
| `important_discoveries` | 约束、决策、错误信息、失败的尝试 |
| `next_steps` | 待办事项、阻塞项、优先级 |
| `context_to_preserve` | 用户偏好、领域细节、做出的承诺 |
| `tool_outputs_summary` | 重要工具调用结果摘要（文件内容、API 响应等） |

自动压缩流程：计算 token（系统提示 + 摘要 + 上下文 + 工具 schema）→ 超过 `trigger_ratio × context_size` 则切分（工具调用/结果对保持成对）→ 较早消息交给 Offloader 卸载并生成摘要替换 → 最近消息保留为新上下文，推理继续。`trigger_ratio` 上限 0.9，剩余空间留给压缩调用本身生成摘要。

> **Token 计数说明**：`core/token_counter.py`（tiktoken，按模型选编码器，CJK 友好）目前用于 `/context` 端点估算与 system_prompt 的调试日志；压缩触发与预算判定暂仍走框架默认估算（factory.py 中有 TODO：将 `count_tokens` 接入 `ContextConfig` 回调）。tiktoken 失败时回退字节估算 `len(utf8)//4`。

### 压缩守卫（ContextGuardMiddleware）

无条件挂在中间件链末尾（factory.py）。`on_compress_context` 钩子在压缩执行前检查 `agent.offloader` 是否已挂载：**未挂载则抛 `RuntimeError` 拒绝压缩**（强制而非告警），防止被压缩的内容永久丢失。本项目始终以 `LocalWorkspaceManager` 作为 offloader，正常路径不会触发。

## 手动压缩

两个入口，最终都调用 `agent.compress_context()` 并保存会话状态：

| 入口 | 说明 |
| ---- | ---- |
| 斜杠指令 `/compact` | 任意传输通道（Web / WebSocket / 渠道）可用；回执形如 `tokens 12000 → 3000（压缩 8 条消息）`（[core/command/builtin.py](../core/command/builtin.py)） |
| `POST /sessions/{user_id}/{session_id}/compress` | REST 手动触发，返回 `messages_compressed` / `tokens_before` / `tokens_after`（[api/chat.py](../api/chat.py)） |

当 token 用量低于 `trigger_ratio × context_size` 时，`compress_context()` 为空操作，可安全地随时调用。另有 `/new` 指令直接开启全新上下文（历史保留、不再携带）。

## 工具结果截断与卸载

每次工具调用后，结果 token 数超过 `tool_result_limit`（15000）即切分：保留部分留在上下文并追加截断标记（含卸载文件路径提示），卸载部分交由 Offloader 持久化，智能体可用 Read/Grep/Glob 按需回查。

本项目 Offloader 即 `LocalWorkspaceManager`（factory.py 中 `offloader=workspace_manager`），卸载文件按**用户私有域**隔离：

```
workspaces/user_spaces/{user_id}/sessions/{session_id}/
├── context.jsonl            # 被压缩的消息，JSONL 追加写
│                            #   每行 {timestamp, role, name, content[]}
└── tool_result-{tool_id}.txt  # 每条被截断的工具结果一个文件
```

- 目录布局与 `_get_workdir` 一致，`GET .../context` 端点读取卸载文件列表时路径天然匹配；
- 会话删除时 `_cleanup_offload_dir` 一并清理该目录；
- `user_id` 必填（用户域隔离），缺失直接抛错。

## 会话恢复：回填与 fork 窗口

会话状态持久化在 KV（Redis / JSONL，`AgentState` JSON）。恢复路径有三条：

1. **KV 命中** —— 直接反序列化 `AgentState`，完整还原（含摘要、注入记录）。
2. **KV 未命中 → PG 回填**（`SessionManager._backfill_from_pg`）—— 从 `conversations` 表加载最近 **`context.backfill_message_limit`（20）** 条，经 `_history_to_state` 转为上下文：
   - **丢弃内部行**：`metadata.type` 为 `thinking` / `tool_call` 的 assistant 行跳过，仅保留 user / assistant 文本（等价于一次「轮内压缩」），与 UI 展示一致；
   - ⚠️ **`context.backfill_token_budget`（15000）当前仅是 schema 预留字段，代码未按 token 截断**，回填实际只按条数限制。
3. **fork 分支**（`SessionManager.fork_session`）—— 复制父会话 PG `conversations` 前缀（支持 `branch_after_message_id` 中途截断）到子会话，从**同一份前缀**重建 `AgentState`（保证 KV == PG），再套用 **`context.fork_window_turns`（10）** 动态窗口：按 user 消息切分轮次，仅保留最近 N 轮。fork 本身不做压缩；系统提示词由 AgentFactory 在 `get_or_create` 时注入，天然保留；进行中的易失状态不携带。

## 上下文用量查询

`GET /sessions/{user_id}/{session_id}/context` —— 前端上下文用量指示器的数据源（api/chat.py）：

| 字段 | 说明 |
| ---- | ---- |
| `estimated_tokens` / `context_window` / `usage_ratio` | tiktoken 精确计数的上下文文本 token / 窗口大小（`llm.context_size`）/ 用量比例 |
| `status` | `healthy`（<0.35）/ `warning`（<0.45）/ `critical`（≥0.45） |
| `trigger_ratio` / `reserve_ratio` | 当前压缩配置，供前端画阈值线 |
| `message_count` | 上下文消息数 |
| `summary_exists` | 是否已存在摘要（`name == "summary"`） |
| `offloaded_files` | 该会话卸载目录下的文件列表（相对路径） |

## 回复预算（与上下文联动）

`ReplyBudgetControlMiddleware`（`middleware.budget_control`，默认启用）在单次回复累计消耗 `input×1 + output×2` 接近 `token_budget`（80000）时，向上下文注入收尾提示（「预算即将耗尽，请总结收尾，不要再调用工具」），引导智能体结束而非硬中断。这与压缩机制互补：压缩管**窗口放不放得下**，预算管**单次回复花多少**。详见 [budget-control.md](budget-control.md)。
